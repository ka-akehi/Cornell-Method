## 3. MVP の状態と MVP / Phase 2 以降の境界

### 3.1 現行 MVP の事実

現行 canonical route は次のとおりです。

- `/` → `/notes` redirect
- `/notes` — 一覧、query、日付、タグ OR、reviewDue、ページング
- `/notes/new` — Canvas 本文、Cue、Summary、タグ、明示保存
- `/notes/[id]` — 閲覧 / 編集 / 詳細画面内復習 / 確認後削除
- `/backup` — 手動 SQLite backup と最新 3 世代確認

主な API は `GET/POST /api/notes`、`GET/PATCH/DELETE /api/notes/:id`、`POST /api/notes/:id/review`、`GET /api/tags`、`GET/POST /api/backups` です。MVP では `/tasks/review`、`/notes/backup`、`GET /api/review-tasks`、`POST /api/undo`、PDF export route はありません。

保存の正本は次のとおりです。

- `bodyMode=canvas` は `NotebookCanvas.documentJson` の `CanvasDocumentV1` を本文の正本とし、`Notebook.body` は空文字です。
- `bodyMode=markdown` は既存 Markdown 本文を互換表示し、Canvas へ自動変換しません。
- Canvas の `searchText` は text element から生成し、一覧検索に使います。用紙寸法だけの変更で要素や `searchText` を自動変形しません。
- 保存は明示保存です。新規は POST 成功後に detail へ遷移し、編集は PATCH 成功後に閲覧へ戻ります。
- 削除は確認後の物理削除です。Undo、soft delete、`SoftDeleteBuffer`、5 秒 Snackbar は MVP にありません。
- 復習は手動 `nextReviewDate` と `reviewedAt` を使い、detail route 内で Cue → 本文 → Summary の想起順を持ちます。専用 review task は Phase 2 です。

新規ノートの次回復習日は `noteDate + 7日` が初期値です。既存ノートの未設定値は自動補完せず、noteDate を変えても明示設定値を自動移動しません。

### 3.2 Phase 2 以降へ送るもの

次は現行 MVP の未実装機能であり、今回の refactor の未達ではありません。

- draft/autosave、3 秒 idle 保存、差分保存、409 optimistic lock、再試行 banner

## 4. Canvas の文言・操作・QA に関する判断

### 4.1 保存契約と操作

- `CanvasDocumentV1` の default page は `1200 x 800`、幅・高さは整数 `320..4000px`、background は `paper` です。
- 入力値は表示倍率ではなく用紙そのものの寸法です。Fit / 50% / 100% / 200% は production の page size として扱いません。
- page resize は `page.width` / `page.height` だけを更新し、既存 element の `x`、`y`、`width`、`height`、`points`、`style`、`rotation`、`text`、`z` を変更しません。境界外の要素も削除・移動・縮小・clip しません。
- `select` は既存要素の選択・移動・resize、`pen` / `line` / `arrow` / `rect` / `ellipse` / `text` は新規作成、`erase` は触れた object 全体の消去です。tool は sticky です。
- line / arrow / rect / ellipse は drag threshold（現行 4px）を超えたときだけ確定します。小さな click / double click は no-op です。
- 図形の double click は図形内文字 inline editor です。外形、既存 stroke、line、arrow、別 shape、standalone text を保持したまま commit/cancel します。
- standalone text は `style`、shape inline text は `textStyle` に文字の style を保存します。Canvas history は client-side snapshot で、DB Undo ではありません。

### 4.2 最終文言とアイコン

実装された文言の履歴は次のとおりです。

1. 実際の挙動が Canvas 全体削除ではなく hit object 単位の消去であるため、「全体消去」を「対象消去」へ変更。
2. さらにペイント系ツール名として自然な「消しゴム」へ変更。
3. group / button の accessible name と tooltip を「消しゴムツール」、説明を「クリックまたはなぞって、触れた要素を消去する」へ統一。
4. ペン形状に見えた `erase` SVG を、厚みのある消しゴム本体と消去面を持つ形状へ変更。

用紙設定の寸法入力、px 表示、適用、validation は残しています。不要と判断した補助文だけを削除し、用紙寸法と表示倍率を分離する契約自体は `MVP_CONTRACT.md` と docs に残しています。

## 6. Target Architecture 要求と strict chain 21〜37

### 6.1 方針転換

Target Architecture は Modular Architecture を主軸とし、`app` は route/HTTP adapter、`modules/notes/ui` は UI、`remote` は HTTP、`contracts` は DTO/validation、`model` は form/view model、`server` は application/infrastructure/presenters、`shared` は domain 非依存部品を担います。禁止依存は次のとおりです。

- `modules/**/ui` → `server/**`
- `modules/**/remote` → Prisma、filesystem、Route Handler 実装
- `server/**` → React component/hook
- repository → HTTP status、`NextResponse`、browser API
- UI → Prisma payload 型
- production Notes → `src/app/spikes/**`

最初の監査で「禁止依存はないので概ね適合」と判定したのは、動作上の問題がないという意味では正しかった一方、Target Architecture の target tree と public boundary を受け入れ基準から外していました。発注者の方針を受け、配置も禁止依存と同じ強さの基準として strict chain へ修正しました。

### 6.3 strict chain の到達点

**事実**: 現在の到達点は次の構造です。

- app route は thin composition。`src/app/notes` は `page.tsx`、`new/page.tsx`、`[id]/page.tsx` の 3 route page のみ。
- `src/modules/notes` は `contracts`、`model`、`remote`、`lib`、`ui/components`、`ui/hooks` を持ち、UI public facade は `ui/components/index.ts`、hooks facade は `ui/hooks/index.ts`。
- Canvas document/history/surface は `src/shared/canvas`、Fabric adapter は `src/shared/canvas/adapters/fabric` が canonical implementation。spike 側の旧 path は互換 facade に限定。
- server は `application`、`infrastructure`、`presenters` に分かれ、Prisma shape は presenter/infrastructure 内に閉じます。
- Tags は module contract → application service → repository → presenter → route の境界を持ちます。
- client-safe HTTP は `src/shared/http/client.ts`、AppChrome bridge は `src/shared/ui/app-chrome-state.tsx` です。
- `src/app/globals.css` は Tailwind + 9 個の local CSS を cascade 順に読む manifest です。
- history は `@/shared/canvas` の public facade からも公開され、module UI の deep import はありません。

**判断**: この状態を strict Target Architecture の受け入れ基準とします。「機能が動きそう」「概ね適合」だけでは完了にしません。禁止依存、配置、public facade、CSS manifest parity のいずれかに違反があれば、動作変更がなくても受け入れません。
