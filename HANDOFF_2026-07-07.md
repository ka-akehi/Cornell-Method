## 会話で決まった重要方針

### アーキテクチャの主軸

当初の `TARGET_ARCHITECTURE.md` では Clean Architecture / Hexagonal Architecture の考え方が強く見えすぎていました。ユーザーから、Next.js はフロントエンド寄りのフレームワークであり、フロントエンド領域まで Clean Architecture を強く入れすぎると複雑化して保守性が落ちる、という指摘がありました。

これを受けて方針を修正済みです。

- 主軸は **Modular Architecture**。
- `notes`, `backup`, `review-tasks`, `export` などの業務機能単位で分ける。
- Clean Architecture / Hexagonal Architecture / Layered Architecture / BFF / Feature-Sliced 的な考え方は補助原則に留める。
- React UI に use case / presenter / repository を機械的に持ち込まない。
- UI は component / hook / remote / model を実用上のまとまりで分ける。
- 追加する層は、重複削減、責務分離、差し替え可能な副作用境界がある場合だけにする。

## 次回 Worker task 作成時の注意

- coding task は `# Worker Task` 直下に `CODEX_TASK_KIND: coding` を付ける。
- 通常 coding task は model 指定不要。Worker が coding kind を見て Spark を試し、使えない場合は通常実行へフォールバックする。
- docs/review task には「コード・設定・依存関係・生成物を変更しない」を制約に明記する。
- `.next` build artifacts は確認対象外と task 制約に明記する。
- 依存しない UI/API/Common task は並行投入してよい。
- 同じ component / file を触る coding task は並行化しない。
- Worker completion は `summary/` の手書き summary を優先し、自動 summary の `.next` ノイズは無視する。
