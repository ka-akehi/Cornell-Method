# Note 欄に図解カードを入れる判断基準

作成日: 2026-07-07

このメモは、学習アプリの UI で「表現力」と「学習サイクルの役割分担」をどう両立するかを学ぶためのメモです。図解カード仕様の正本や実装指示ではありません。仕様化する場合は `AGENTS.md`、`doc/`、該当 task で改めて決めます。

## このメモで学ぶこと

- Cue / Note / Summary は同じ入力欄ではなく、それぞれ違う学習行為を支える領域であること。
- 図解は便利だが、どこに置くかで復習、検索、PDF、アクセシビリティへの影響が変わること。
- hover や無限キャンバスのような見た目の魅力だけで主方式を選ぶと、利用場面によって破綻しやすいこと。

## なぜ重要か

学習ノートでは、関係図や流れ図の方が文章より理解しやすい場面があります。一方で、すべてを自由なキャンバスにすると、Cornell Method の「Cue を見て Note を思い出し、Summary で言語化する」流れが曖昧になります。

この判断では、機能を増やすことよりも、どの領域にどんな表現を許すと学習行為を助けるのかを考えることが重要です。

## 判断の基本

図解を検討するときも、Cue / Note / Summary の役割を崩さないことを優先します。

- Cue は、思い出すための手がかりなのでテキスト中心に考える。
- Note は、記録本体なので図解が学習理解を助ける余地がある。
- Summary は、理解を自分の言葉で締める場所なのでテキスト中心に考える。

図解は Note 欄の表現力を広げる補助であり、Cue 作成や Summary の言語化を置き換えるものではありません。

## 初心者が誤解しやすい点

- 図解が便利なら、すべての欄で自由描画できる方がよいと思う。
- hover 表示を、補助ではなく主情報の表示手段にする。
- 無限キャンバスの自由度と、検索、復習、PDF、アクセシビリティの扱いやすさを同時に満たせると思う。
- 図解 UI だけに注目し、保存形式、代替テキスト、出力、検索を見落とす。

## 判断で見る論点

- 図解は「記録」「整理」「想起」のどこを助けるか。
- Note 欄の通常情報として見える必要があるか、補助表示で足りるか。
- スマートフォン、キーボード操作、PDF 出力でも情報が失われないか。
- テキスト検索やタグ検索とどう共存するか。
- 図解のタイトル、説明、代替テキストをどう扱うか。
- 保存形式や編集方式を、初回から固定する必要があるか。

## 次に同じ判断をするときの見方

見た目の自由度だけで判断せず、復習、検索、出力、アクセシビリティまで含めて考えます。図解カードを仕様化する場合は、このメモを出発点にしつつ、`doc/screens/`、`doc/requirements/`、`doc/technical/` 側へ正本として整理します。
