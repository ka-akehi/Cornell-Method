# Cornell Method Notebook の学習サイクル中心軸

作成日: 2026-07-07

このメモは、Cornell Method Notebook の中心目的を「ノート保存」ではなく「学習サイクル」として捉えるための学習メモです。UI 要件や仕様指示の正本ではありません。実装時は `AGENTS.md` と `doc/requirements/`、`doc/screens/` を確認します。

## このメモで学ぶこと

- 機能一覧から設計を始めるのではなく、ユーザーが回したい学習行為から考えること。
- Cue / Note / Summary の分離はレイアウト都合ではなく、記録、整理、要約、想起、復習を支えるためにあること。
- 周辺機能は便利さではなく、学習サイクルのどこを支えるかで優先度を判断すること。

## なぜ重要か

CRUD、タグ、検索、PDF、自動保存などを個別に見ると、どれも必要に見えます。しかし中心軸がないと、アプリは Cornell Method Notebook ではなく多機能なメモアプリへ寄りやすくなります。

学習サイクルを先に固定すると、MVP に入れる機能、後回しにする機能、削る機能を説明しやすくなります。

## 中心に置く学習行為

判断の軸は、次の流れをアプリ上で回せるかです。

1. 記録する
2. 整理する
3. 要約する
4. 想起する
5. 復習する

この流れのどこにもつながらない機能は、主要導線へ入れる前に目的を確認します。

## Cue / Note / Summary の見方

- Cue は、本文を隠したときに思い出すための手がかり。
- Note は、学習中に得た内容を残す記録本体。
- Summary は、本文とは別に自分の言葉で理解を再構成する場所。

3 領域の分離は、入力フォームの都合ではありません。記録、整理、要約、想起、復習を分けて支援するための構造です。

## 初心者が誤解しやすい点

- 3 欄を作れば Cornell Method になると思う。
- 便利な周辺機能を足すほど学習体験が良くなると思う。
- CRUD や検索の実装可否を先に考え、学習行為との関係を後回しにする。
- 復習をタスク管理だけで捉え、Cue から思い出す行為を見落とす。

## 機能追加時の判断質問

- これは記録、整理、要約、想起、復習のどこを支えるか。
- そのフローを成立させるために必須か、便利にするだけか。
- Cue / Note / Summary の役割を曖昧にしないか。
- 学習中の入力、整理、復習の流れを止めないか。
- 補助機能が中心体験より目立っていないか。
- 後から追加してもデータ構造や画面導線を大きく壊さないか。

## 次に同じ判断をするときの見方

機能名ではなく、その機能が支える学習行為を先に書きます。仕様として採用するかどうかは、このメモだけで決めず、`AGENTS.md`、`doc/requirements/`、`doc/screens/` の正本と照合します。
