## 完了済みの範囲

### Desktop foundation

- stable `settings/.instance.lock` を authority とする advisory lock、`settings/.instance.owner` の atomic replace、focus socket、bounded retry、stale socket recovery、active / unknown / permission endpoint の fail-safe を実装済み。
- secondary は focus 成功または `AlreadyRunningNotReady` で終了し、Tauri window / sidecar を作らない。primary の ready 後の window 作成、window state、close decision、sidecar / app-owned child process cleanup のコード境界がある。
- dynamic loopback の sidecar ready handshake と cleanup の実装はあるが、実プロセスでの確認は未完了である。

### Settings / responsibility audit

- Mac の Settings menu は新しい window や runtime を作らず、既存 primary WebView へ shared event を送る。
- Web gear / mobile trigger と Mac menu は同じ Settings bridge を使う。modal は General、Updates、Data and Backup の3カテゴリを持つ。
- `main.rs`、Rust lifecycle / runtime / instance module、AppChrome、close coordinator、editor dirty controller、Summary draft controller の責務抽出を完了し、最終 audit は「現時点で追加分割不要」と判定した。

### Update pipeline（backend 実装済み・packaged runtime 未検証）

- 現行コードには GitHub Releases provider、provider-neutral manifest の parsing / normalization / strict validation、compatible selection、公開 direct HTTPS URL 境界、package download、公開鍵署名・SHA-256 検証、archive / bundle validation、atomic な update state、pending update verification / staging revalidation がある。`apply_verified_update` は `Available` かつ `Verified` の candidate に対する引数なしの明示 command だけで起動し、candidate identity、signature・digest、canonical staging path、archive、bundle ID / version / architecture / arm64 Mach-O を再検証して `ApplyPreparation` を atomic に保存し、explicit restart handoff へ渡す。
- persisted `ApplyPreparation` を起点に、pending migration がある場合だけ migration 前 safety backup と DB staging copy を作成し、候補 DB の古い順の migration、schema / integrity / foreign key / reopen、既存列と Notebook / Canvas / legacy Markdown の read-back を確認してから atomic switch する。pending migration がない場合は migration と safety backup を行わない。
- `RestartHealthCheck` の `HealthPending` / `BundleSwitching` / `BundleSwitched` / `CleanupPending` / `RollbackPending` checkpoint は atomic に永続化される。candidate/current の path、symlink、bundle identity、version、architecture を検証し、candidate health には packaged app bundle root ではなく固定 runtime root `Contents/Resources/runtime` を渡す。candidate health 成功前は current app / live DB / safety backup を保持し、成功後だけ旧 bundle、staged artifact、不要な safety backup を cleanup する。
- rollback、SQLite restore、旧 bundle への復帰、不要な staged artifact の cleanup、typed failure は fail-closed に扱い、failure / interruption 後に staged migration を自動再実行しない。`node --test test/desktop/desktop-update-*.test.js` は 54/54 PASS（rollback/recovery focused tests 6/6 を含む）。これは disposable fixture と static contract の証跡であり、実 provider / package runtime や packaged GUI の PASS ではない。
