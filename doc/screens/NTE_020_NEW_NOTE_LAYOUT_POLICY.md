## 判断対象

判断対象は、新規ノート作成時に次の情報をどの密度と近接関係で見せるかです。

- 基本情報: タイトル、学習日、学習元、タグ
- Cornell Layout: Cue / キーワード / 質問、ノート本文 Markdown、本文 Preview
- Summary: サマリー Markdown、Summary Preview、次回復習日、キャンセル / 保存

## 現行実装の長所

- 入力欄が大きく、初回利用者でも各フィールドの意味を読み取りやすい。
- 基本情報、Cornell ノート、サマリーが大きなカードで分かれており、画面構造が明確。
- タグ入力は「既存タグから追加」と「新規タグ入力」が分かれているため、機能の違いを理解しやすい。
- ノート本文と Summary の textarea が広く、長文入力に向いている。
- Preview が各入力の直下にあるため、Markdown の確認先を見失いにくい。
- 基本情報、Cornell ノート、サマリーの大きな区切りは、狭い画面でも表示順序を保ちやすい。

## 現行実装の課題

- 画面が縦に長く、保存操作までの距離が遠い。
- 新規作成開始時に、Cue、本文、Preview、Summary の全体像が一度に見えにくい。
- 基本情報カードの余白が大きく、入力密度に対して画面占有が大きい。
- タグ入力が 2 段になっており、タグを素早く追加する操作としては距離がある。
- ノート本文の Preview が textarea の下にあるため、デスクトップでは Markdown 入力と表示結果を同時比較しにくい。
- Cue 追加ボタンが Cue 見出しと離れており、対象領域との近接性が弱い。

## PNG ワイヤフレーム案の長所

- 基本情報、Cornell Layout、Summary が短いスクロールで把握できる。
- Cue、本文、Preview が近く、Cornell Method の「左に問い、右に本文」の関係が見えやすい。
- デスクトップでは本文 textarea と Preview が横並びで、Markdown 入力と結果確認の往復が短い。
- Cue 追加ボタンが Cue 見出し右にあり、対象に対する操作だと分かりやすい。
- Summary、次回復習日、保存操作が近く、作成完了までの流れが見えやすい。
- Cornell Layout が画面の中心にあり、このアプリの主目的が伝わりやすい。

## PNG ワイヤフレーム案の課題

- 圧縮が強く、長文入力や Summary の編集には窮屈になる可能性がある。
- Summary を 1 行に近い形で扱うと、要約と次アクションを Markdown で書く仕様に対して入力欄が不足しやすい。
- タグ入力は効率的だが、既存タグ候補と新規タグ作成の違いが現行実装より見えにくい。
- 画面 ID や英語見出しなど、設計成果物用の表示が含まれており、実画面としては整理が必要。
- Cue のサンプル表示は構造説明には有効だが、新規作成初期状態としては空状態との扱いを決める必要がある。
- 横並びを増やすため、タブレットやモバイルでは横スクロール領域と通常の縦スクロール領域の境界を明確にする必要がある。

## 選択肢

### A: 現行実装を正として維持し、ワイヤフレームを合わせる

現行実装のカード分割、広い入力欄、縦積み Preview を正とし、PNG ワイヤフレームは実装確認用の成果物として現行画面に寄せます。

| 観点 | 影響 |
| --- | --- |
| 学習体験 | 画面を上から順に埋める体験は分かりやすい。一方、Cornell 構造の全体像は後半まで見えにくい。 |
| 入力効率 | 長文入力はしやすいが、基本情報から保存までの移動距離が長い。 |
| Markdown preview | 入力欄の下に Preview を置くため確認先は明確。ただしデスクトップで同時比較しにくい。 |
| Cue / Note / Summary の関係 | セクション単位の分離は明確だが、Cue と本文、Summary の学習上のつながりは弱く見える。 |
| 実装コスト | 最小。既存実装を維持し、ワイヤフレーム側の修正だけで済む。 |
| モバイルへの影響 | Cornell Layout の関係性より単純な縦順序を優先するため、今回の方針とは合わない。 |

### B: ワイヤフレーム案を基本方針として、実装改善候補にする

PNG ワイヤフレームの情報密度と近接性を基本方針にし、現行実装を大きく圧縮します。

| 観点 | 影響 |
| --- | --- |
| 学習体験 | Cornell Layout が早く見えるため、左の Cue と右の本文の関係を意識しやすい。 |
| 入力効率 | 保存までの距離が短く、本文入力と Preview 確認の往復も短い。 |
| Markdown preview | デスクトップでは本文 textarea と Preview を横並びにできる。Summary の Preview は狭くなりやすい。 |
| Cue / Note / Summary の関係 | 1 画面内で関係が見えやすい。特に Cue と本文の近接性が強い。 |
| 実装コスト | 中から高。基本情報、タグ、本文、Summary、レスポンシブの再設計が必要。 |
| モバイルへの影響 | 横並び前提の要素が増えるため、Cornell Layout 部分を横スクロールで扱う設計が必要になる。 |

### C: 折衷案として、実装の明確さを残しながらワイヤフレームの情報密度と近接性を取り入れる

現行実装の「分かりやすい入力欄」と「セクションの明確さ」は残し、基本情報の圧縮、Cue / 本文 / Preview の近接、保存操作の近さを取り入れます。

| 観点 | 影響 |
| --- | --- |
| 学習体験 | セクションの意味を保ちながら、Cornell Layout の全体像を早く見せられる。 |
| 入力効率 | 基本情報とタグの操作距離を短くし、本文入力と Preview 確認の往復も減らせる。 |
| Markdown preview | 本文はデスクトップで横並び Preview、Summary は縦並び Preview を維持できる。用途に応じて扱いを分けられる。 |
| Cue / Note / Summary の関係 | Cue と本文は一体感を強め、Summary は締めの領域として下部に残せる。 |
| 実装コスト | 中。全画面作り直しではなく、レイアウト再配置中心で進められる。 |
| モバイルへの影響 | Cornell Layout の横方向の関係を維持し、狭い画面では横スクロールを許容する。モバイルでの編集効率最適化は MVP / 近い改善対象から外す。 |

## Manager 推奨

Manager は C を推奨します。

C は、現行実装の「入力欄の分かりやすさ」と「セクションの明確さ」を保ち、ワイヤフレームの「全体像の見えやすさ」「Cue / 本文 / Preview の近さ」「保存までの移動距離の短さ」を取り込めます。

A は大きな入力欄と縦積み Preview を保つため実装変更が少ない一方、Cornell Layout が初期表示から外れやすい案です。B は Cornell Layout と保存操作を近づけられますが、Summary とタグ入力が狭くなり、変更範囲も広がります。C は基本情報を圧縮して Cue / 本文 / Preview を近づけ、Summary の編集幅を保ちます。狭い画面では Cornell Layout 内だけを横スクロールさせるため、デスクトップ / 横長画面を主対象にしながら変更範囲を抑えられます。

## 推奨案 C を採用する場合の UI 決定事項

### 全体レイアウト

- ページ見出しは現行実装の日本語 `新規ノート` を維持する。
- 設計成果物用の `NTE-020` や `New Note` は実画面には表示しない。
- 大きなカード 3 枚構成は維持するが、基本情報カードの高さを圧縮する。
- 新規ノート画面は、デスクトップ / 横長画面での作成・編集を主対象にする。
- デスクトップでは、初期表示または短いスクロールで Cornell Layout の開始位置が見えることを目標にする。
- 画面幅は現行のコンテンツ幅を基本にし、カード内の余白を減らして情報密度を上げる。

### 基本情報

- タイトルと学習日は同一行に置く。タイトルを主、学習日を右側の短い入力にする。
- 学習元タイプと学習元タイトルは同一行に置く。
- タグは 1 つの入力行に寄せる。候補選択と新規追加の体験は実装仕様に合わせて残すが、上下 2 段で大きく分断しない。
- 選択済みタグチップはタグ入力の近くに表示する。

### Cornell Layout

- Cue とノート本文は 30% / 70% の基本比率を維持する。
- Cue 見出し右に `+` または小さな `Cue 追加` ボタンを置き、追加対象との近接性を高める。
- 新規作成初期状態の Cue には空状態を表示し、サンプルは入れない。
- 本文エリアはデスクトップで textarea と Preview を横並びにする。
- 本文 textarea を Preview より広くする。例: textarea 55%、Preview 45%。
- Preview は表示専用で、チェックボックスはクリックしても編集されない仕様を維持する。

### Summary

- Summary はワイヤフレームのような 1 行圧縮にはしない。
- Summary textarea と Preview は現行に近い縦並びを維持する。ただし高さは現行より少し抑える。
- 次回復習日、キャンセル、保存は Summary カード下部の同一行に置く。
- 保存ボタンは最下部右側に置く。可能であればデスクトップではカード下部が見えやすいよう Summary の高さを抑える。

### モバイル

- モバイルでも Cornell Layout の横方向の関係を維持する。
- Cue / Note / Preview の関係を保つため、Cornell Layout 部分は横スクロールを許容する。
- モバイルの受け入れ条件は、横スクロールで構造を維持し、各操作へ到達できることとする。
- モバイルでの本格的な編集効率最適化は MVP / 近い改善対象から外す。
- 基本情報と Summary は通常の縦スクロールで読める構造にし、横スクロールは主に Cornell Layout 部分へ閉じ込める。
- タグ入力は入力、追加ボタン、チップが折り返しても読めるようにする。
- 保存 / キャンセルは最下部に置く。sticky footer は MVP では必須にしない。

### Markdown preview の扱い

- 本文 Preview は Cornell Layout の一部として本文入力の横に置く。
- Summary Preview は Summary の確認として textarea の下に置く。
- Preview の表示は空状態を維持し、初期サンプル Markdown は入れない。

## 採用しない案と理由

| 案 | 採用しない理由 |
| --- | --- |
| A: 現行実装維持 | 現行は安定しているが、ユーザーが違和感を持った縦長さと全体像の見えにくさを解消できない。Cornell Method の関係性を早く見せる改善機会を逃す。 |
| B: ワイヤフレーム全面採用 | 情報密度は良いが、Summary とタグ入力が圧縮されすぎる。長文 Markdown 入力、モバイル、既存タグ候補の扱いで再設計コストが大きい。 |

## 低忠実度テキストワイヤフレーム

推奨案 C のデスクトップ方針です。

```text
+------------------------------------------------------------------+
| 新規ノート                                                       |
+------------------------------------------------------------------+
| 基本情報                                                         |
| タイトル [________________________________________] 学習日 [date] |
| 学習元タイプ [select v] 学習元タイトル [_______________________] |
| タグ [候補/新規タグ入力________________] [追加] [tag x] [tag x] |
+------------------------------------------------------------------+
| Cornell ノート                                                   |
| +----------------------------+ +-------------------------------+ |
| | キーワード / 質問      [+] | | ノート本文 Markdown           | |
| | +------------------------+ | | +-------------+ +-------------+ | |
| | | Cue は未追加です。     | | | | textarea    | | Preview     | | |
| | +------------------------+ | | |             | |             | | |
| |                            | | +-------------+ +-------------+ | |
| +----------------------------+ +-------------------------------+ |
+------------------------------------------------------------------+
| サマリー                                                         |
| [サマリー Markdown textarea                                      ] |
| Preview                                                          |
| [サマリーのプレビューはまだありません。                         ] |
| 次回復習日 [date]                         [キャンセル] [保存]    |
+------------------------------------------------------------------+
```

モバイルでは、基本情報と Summary を画面幅に合わせて縦に流し、Cornell Layout 部分を横長の作業面として維持します。狭い画面でも Cue / ノート本文 / Preview の横方向の関係を保ち、Cornell Layout 内で横スクロールできるようにします。

```text
+------------------------------+
| 新規ノート                   |
+------------------------------+
| 基本情報                     |
| タイトル [_________________] |
| 学習日 [date]                |
| 学習元タイプ [select v]      |
| 学習元タイトル [___________] |
| タグ [________] [追加]       |
| [tag x] [tag x]              |
+------------------------------+
| Cornell ノート               |
| <横スクロール領域>           |
| +----------------------------+ +----------------------------+ |
| | キーワード / 質問      [+] | | ノート本文 Markdown        | |
| | Cue は未追加です。         | | +------------+ +----------+ | |
| |                            | | | textarea   | | Preview  | | |
| |                            | | +------------+ +----------+ | |
| +----------------------------+ +----------------------------+ |
| </横スクロール領域>          |
+------------------------------+
| サマリー Markdown            |
| [textarea]                   |
| Preview                      |
| [Markdown preview]           |
| 次回復習日 [date]            |
| [キャンセル] [保存]          |
+------------------------------+
```
