# コーネルメソッド観点の仕様レビュー

確認日: 2026-06-14

## 目的

このドキュメントは、現行の仕様案が「コーネルメソッドを活用したノートアプリ」として適切かを確認するためのレビューです。

現行実装はフルリニューアル前提のため、ここでは既存コードではなく To-Be 仕様の妥当性を評価します。

## 前提: コーネルメソッドで支援すべき流れ

コーネルメソッドは、単に画面を 3 分割するだけではなく、学習プロセスを支援するノート術です。

本アプリで支援すべき基本フロー:

1. 記録する
   - 授業、読書、動画、調査などからノート本文を書く。
2. 整理する
   - 左欄にキーワード、質問、論点、用語を抜き出す。
3. 要約する
   - 下部に自分の言葉で要点をまとめる。
4. 想起する
   - キーワード / 質問だけを見て、ノート本文を思い出す。
5. 復習する
   - 時間を置いて再確認し、理解度を更新する。

このため、アプリの中心は「保存できること」だけではなく、**あとで思い出す・理解を確認する・復習する**ことに置くべきです。

## 現行仕様案の良い点

| 観点 | 評価 |
| --- | --- |
| Cornell レイアウト | キーワード欄、ノート欄、サマリー欄があり、基本構造は合っている |
| Markdown | 箇条書き、チェックリスト、強調を扱えるため学習ノートと相性が良い |
| タグ | 科目、テーマ、教材、試験範囲などで整理できる |
| 日付 | 学習記録、復習タイミング、時系列確認に使える |
| 一覧検索 | 後から探して読み返す用途に必要 |
| 復習タスク | コーネルメソッドの「Review」に近く、方向性は良い |

## 現行仕様案の問題点

| ID | 問題 | 影響 |
| --- | --- | --- |
| P-001 | CRUD、タグ、PDF、自動保存などのアプリ機能が先行している | コーネルメソッドの学習体験が仕様の中心から外れる |
| P-002 | 「想起する」ための仕様が弱い | 左欄を見て右欄を思い出す練習ができない |
| P-003 | サマリー欄が単なる Markdown 欄になっている | 自分の言葉で要約する行為を促せない |
| P-004 | 復習タスクが Phase 2 扱いになっている | Cornell Method の Review を MVP で支援しない設計になり得る |
| P-005 | カード単位や D&D が先に複雑化している | ノートを書く流れより UI 操作の複雑さが目立つ |
| P-006 | タグ仕様が細かすぎる | 学習体験より管理機能に設計コストが寄る |
| P-007 | PDF 出力の優先度が高く見える | 学習中の活用より成果物出力に寄る |
| P-008 | 「ノート本文」と「キーワード/質問」の関係が機械的すぎる | 実際の Cornell Note では、厳密なカードリンクより人間が見て思い出せる配置が重要 |

## 仕様として見直すべき中心軸

MVP の中心は、以下に置くべきです。

> ノートを保存するアプリではなく、コーネルメソッドの「記録、整理、要約、想起、復習」を回せるアプリにする。

そのため、MVP に含める機能は「便利機能」ではなく、学習サイクルに直接関係するものを優先します。

## To-Be で重視する体験

### 1. 書く

- ノート本文を素早く書ける。
- 講義中、読書中、動画視聴中でも入力を邪魔しない。
- Markdown は使えるが、UI が Markdown 記法の習得を強制しない。

### 2. 整理する

- 後からキーワード、質問、用語、論点を左欄に追加できる。
- 左欄は「本文の見出し」ではなく、あとで思い出すための手がかりとして扱う。
- キーワード欄とノート本文の厳密な紐付けは、MVP では必須にしない。

### 3. 要約する

- サマリー欄は目立つ位置に置く。
- 未入力の場合に「要約未作成」とわかる。
- 要約は本文とは別に保存する。

### 4. 想起する

- キーワード / 質問だけを表示し、ノート本文を一時的に隠せる。
- その状態で自分の記憶を確認できる。
- MVP では採点や理解度管理までは不要。

### 5. 復習する

- 復習対象のノートがわかる。
- MVP では高度な間隔反復ではなく、簡単な「復習予定日」または「復習済み」でもよい。
- 復習機能を完全に Phase 2 に落とすと、コーネルメソッドらしさが弱くなる。

## MVP を見直す場合の推奨範囲

### MVP に含めるべきもの

| 機能 | 理由 |
| --- | --- |
| ノート作成・編集・保存 | 基本 |
| Cornell レイアウト | 中核 |
| キーワード / 質問欄 | 想起の手がかり |
| ノート本文欄 | 記録の中心 |
| サマリー欄 | 要約の中心 |
| Markdown 入力・表示 | 学習ノートとして有用 |
| ノート一覧 | 読み返しの入口 |
| タイトル検索 | 最低限の検索 |
| タグ | 科目・テーマ分類 |
| 日付 | 学習日と復習の基準 |
| 本文を隠す復習モード | Cornell Method の想起を支援するため |
| 要約未作成の表示 | 要約習慣を促すため |
| 復習予定日または復習済みフラグ | Review を MVP に薄く含めるため |
| 最低限バックアップ | ローカル利用の安全性 |

### MVP から外してよいもの

| 機能 | 理由 |
| --- | --- |
| PDF 出力 | コーネルメソッドの実践には直接不要 |
| D&D 並び替え | 最初は上下移動または作成順で十分 |
| 自動保存 | 便利だが学習フローの中核ではない |
| 楽観ロック | 個人ローカル利用では優先度が低い |
| Undo スナックバー | 削除確認で代替可能 |
| 複雑なタグ管理 | 科目・テーマ分類ができれば十分 |
| カード間の厳密な多対多リンク | MVP では学習体験より実装複雑度が勝つ |
| 高度な復習アルゴリズム | まずは復習対象がわかればよい |

## DB 設計への示唆

MVP では、以下のようなシンプルな構造を優先します。

- `Notebook`
  - title
  - noteDate
  - sourceType
  - sourceTitle
  - overview
  - body
  - summary
  - reviewModeEnabled or reviewStatus
  - nextReviewDate
- `Cue`
  - notebookId
  - text
  - order
- `Tag`
  - name
- `NotebookTag`
  - notebookId
  - tagId

検討ポイント:

- ノート本文はカード分割せず、MVP では 1 つの Markdown 本文でもよい。
- キーワード / 質問は複数行または単純なリストでよい。
- Note と Cue の多対多リンクは Phase 2 でよい。

## UI 設計への示唆

MVP の詳細画面は、以下の状態を持つとよいです。

- 編集モード
  - 右欄に本文を書く。
  - 左欄にキーワード / 質問を書く。
  - 下部にサマリーを書く。
- 閲覧モード
  - Cornell レイアウトで読む。
- 復習モード
  - 左欄とサマリーを表示。
  - ノート本文は隠す / 表示するを切り替える。

## Manager 評価

現行仕様は、コーネルメソッドの基本レイアウトは押さえています。しかし、アプリ機能の網羅性が先行しており、コーネルメソッドの学習サイクル支援としてはまだ弱いです。

特に MVP では、PDF や D&D よりも、**本文を隠してキーワードから想起する復習モード**を優先した方が、このアプリの目的に合います。
