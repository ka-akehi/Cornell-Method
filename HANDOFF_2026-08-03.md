## 3. Issue #85 / #86

### Issue #85 — pathname change 時に mobile navigation を閉じる

- 根本原因: pathname が変わっても `isMobileNavOpen` が残り、mobile overlay が開いた状態を次の route へ持ち越し得ました。
- 修正: `pathname` を依存値とする effect を追加し、`requestAnimationFrame` 内で `setIsMobileNavOpen(false)` を実行します。unmount 時は frame を cancel します。pathname change では通常の close handler を呼ばず、旧 trigger への focus 復帰も行いません。既存の Escape / backdrop / close 操作と body-scroll cleanup は維持しています。
- commit: `d104156` (`fix mobile navigation on pathname changes`)
- 検証: responsive contract test が pathname-change effect と、そこから `closeMobileNav` / mobile trigger focus を呼ばないことを確認しています。

### Issue #86 — collapsed rail handle を全面表示する

- 根本原因: rail が collapsed のとき、2.75rem の edge handle が `translateX(50%)` のままで、rail 側の clipping により hit area の一部が画面外へ出る可能性がありました。
- 修正: open state の edge placement は維持し、collapsed state では `.app-chrome-shell.is-rail-collapsed .app-chrome-rail-handle` を `translateX(100%)` として main-content 側へ移動し、handle 全体を表示します。
- commit: `b5b65f5` (`keep collapsed rail handle fully visible`)
- 検証: responsive contract test が collapsed state の `translateX(100%)` と、既存のサイズ・focus-visible 契約を確認しています。

### Issue #88 — desktop rail 内の focus を mobile menu button へ復帰する

- 根本原因: breakpoint により desktop rail が非表示になるとき、rail 内の brand / navigation link / create link が `document.activeElement` であっても、focus 復帰判定の対象に含まれていませんでした。そのため、表示中の mobile menu button へ focus が戻らない経路がありました。
- 修正: desktop rail の `aside` を `desktopRailRef` で参照し、`desktopRailRef.current?.contains(document.activeElement) === true` を active element 判定へ追加しました。desktop rail 内に focus がある状態で mobile breakpoint へ切り替わった場合、mobile menu button へ focus を復帰します。既存の mobile navigation / rail handle の focus 挙動は維持しています。
- commit: `2a4db5e` (`fix: restore focus when desktop rail hides`)
- 検証: `app-chrome-responsive-contract.test.js` が rail ref、`contains(document.activeElement)` 判定、および rail 内の brand / navigation / create link の markup を確認しています。これは static contract であり、実ブラウザの focus acceptance ではありません。

### Issue #89 — accent-filled controls の通常文字コントラストを是正する

- 根本原因: `--app-accent` を背景に淡色文字を重ねる filled control が、通常サイズ文字の WCAG AA 基準 4.5:1 を満たしていませんでした。影響範囲は notes list、backup、Cue、AppChrome、note paper の filled state です。
- 修正: filled control の背景・border を `--app-accent-deep` に寄せ、notes list の新規作成、backup 作成、Cue 番号、AppChrome の selected create link、note paper の submit button の組み合わせを更新しました。AppChrome の selected navigation は `--app-accent-deep` 文字と `--app-accent-soft` 背景の組み合わせを維持します。
- commit: `fd0370c` (`fix: improve accent control contrast`)
- 検証: `accent-contrast-contract.test.js` が実色値からコントラスト比を計算し、notes list、backup、Cue、AppChrome、note paper の通常文字を WCAG AA 4.5:1 以上として確認します。semantic state と既存の focus / disabled 契約も関連 contract で確認しています。これは static color contract であり、実ブラウザの描画確認ではありません。
